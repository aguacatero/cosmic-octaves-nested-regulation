# Scientific Rigor Audit

**Date:** 2026-09-19  
**Purpose:** Give an outside reviewer a transparent snapshot of methodological readiness across the project.  
**Method:** `docs/methodology/scientific-rigor-gate.md`

This audit is **not a truth score**. It asks whether each branch has the methodological infrastructure needed to make a confirmatory scientific claim.

Allowed gate states: `PASS`, `PARTIAL`, `FAIL`, `BLOCKED`, `N/A`.

---

## Bottom line

The repository is now stronger as a **research architecture** than as an **empirical evidence base**.

Its strongest features are:

- explicit separation of observations, source claims, interpretations, project hypotheses, and predictions;
- preservation of invalidated and blocked work;
- explicit rival explanations and adversarial evidence;
- branch isolation and no automatic evidence inheritance;
- a publication strategy centered on narrow tests rather than the grand synthesis.

Its largest remaining weaknesses are cross-cutting:

1. systematic literature-search boundaries are not yet complete for every branch;
2. several constructs are not yet operationalized tightly enough for independent implementation;
3. power/precision/information-content plans are mostly absent because final designs are not frozen;
4. clean discovery/confirmation holdouts are unresolved for the highest-priority empirical branches;
5. executable confirmatory pipelines and locked computational environments are not yet present;
6. no independent methods review has yet cleared a branch for confirmation;
7. no branch has yet produced a new preregistered confirmatory result under the v3 rigor gate.

Accordingly, **no grand nested-regulation, agency, or consciousness claim is currently supported by this audit.**

# Cross-cutting priority queue

## P0 — VASCO confirmation architecture

1. Complete GitHub Issue #3.
2. Freeze canonical dataset versions/checksums and unit of inference.
3. Build the supportive-vs-critical prediction/rival matrix.
4. Choose a genuinely untouched confirmation strategy or explicitly conclude that current data can support only reanalysis, not independent confirmation.
5. Define primary model, precision/information rationale, multiplicity, negative controls, and sensitivity policy.
6. Build executable analysis/tests/environment.
7. Obtain astronomy/survey-systematics and statistical methods review.
8. Submit Stage 1 Registered Report or immutable preregistration before confirmation.

## P1 — Scale confirmation redesign

1. Treat existing 15-structure work as discovery/exploration.
2. Define a genuinely independent measurement/selection replication.
3. Freeze comparable size conventions and uncertainty propagation.
4. Define the smallest recurrence pattern worth discriminating and a test that can distinguish recurrence from selection/null ensembles.
5. Obtain independent statistics/measurement review before holdout analysis.

## P1 — Regulation calibration

Implement the detector on known positive and negative systems. If it cannot reliably distinguish feedback regulation from passive/autocorrelated dynamics, stop and revise before any exotic application.

## P2 — Network model operationalization

Finish Jackson provenance work; freeze topology-only motifs, role classes, relay/timing predictions, and generative nulls before choosing confirmation cases.

## P2 — Observer masking feasibility

Identify a dataset or feasible study with simultaneous objective/independent channels and uncontaminated observer reports. Validate the measurement problem before attempting a mechanism claim.

## P3 — Bridges, cross-level influence, and system consciousness

Remain downstream until their parent branches satisfy the appropriate gates.

# What would materially increase confidence in this repository?

The next major increase in scientific confidence will not come from adding more conceptual synthesis. It will come from completing one narrow branch end-to-end:

```text
reproducible evidence search
        ↓
serious rival hypotheses
        ↓
validated measurement
        ↓
frozen study + statistical design
        ↓
untouched confirmation data
        ↓
immutable preregistration / Stage 1 review
        ↓
reproducible confirmatory execution
        ↓
independent replication
```

For this project, **V-A / VASCO is currently the best candidate to do that first**.
